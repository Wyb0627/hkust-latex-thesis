                                        CHAPTER 4

       ADAPTIVE GRAPH RETRIEVAL FOR DYNAMIC
                    CLASSIFICATION WITH GORAG

   This chapter is based on GORAG: Graph-based Online Retrieval Augmented Generation for
Dynamic Few-shot Social Media Text Classification, published in the Proceedings of the ACM
Web Conference 2026 [1]. It studies the selection and maintenance of label evidence when
a classification task acquires new classes over several rounds. The central question is how a
language model can receive a query-specific candidate set while the evidence connecting text to
labels changes over time.



4.1     Dynamic Few-shot Classification
A classification label defines a decision that an application asks a model to make. When the
application adds a more specific category, the decision changes even if the underlying language
model stays fixed. For example, a social media classification task can initially distinguish threat-
ening language and later introduce identity insults. A model must then distinguish the new label
from earlier labels using the available annotated examples. The diﬀiculty concerns both learning
the meaning of a new category and keeping the current alternatives visible during prediction.
   Few-shot classification supplies a small number of labeled examples for each class. Dynamic
few-shot classification adds classes in successive rounds [2]. The size of the label universe
therefore grows independently of the number of examples available for each label. A retrieval
system must update its evidence source as classes arrive, and each prediction must refer to the
label set available at that round. This setting differs from repeatedly evaluating a fixed classifier
on an unchanged collection of labels.
   The task also exposes a limitation of simply placing more material in a language model’s
context. Additional examples provide information about labels, but a larger context can contain
many examples that have little bearing on the current text. The candidate list itself grows as
classes accumulate. Selecting text passages without narrowing the associated label alternatives
leaves the model with a long classification instruction. GORAG therefore treats the selection of
candidate labels as an explicit retrieval problem.

   The index used in this chapter is a weighted graph of keywords and labels. A keyword can
occur in examples from several classes. Its incident edges record these associations, and their
costs distinguish how the term is represented in the indexed corpus. The graph allows several
query keywords to be considered jointly. A label can participate in the connection between
query keywords even when examining one keyword in isolation would give an ambiguous set of
alternatives. The retrieved label set depends on the query terminals and the current graph.
   GORAG also updates its index after classifying an unlabeled query. Keywords that were
absent from the index can then become available to later queries. The associated label is the
model’s prediction, which introduces an important distinction between supervised initialization
and subsequent online expansion. The system receives true labels for the few-shot support exam-
ples; it does not receive the true label of a query before predicting that query. This information
boundary defines the interpretation of the online evaluation.
   The research question has three connected parts. First, how should a small support set be-
come a graph whose edges distinguish keyword–label associations? Second, how should the
graph select a different candidate set for each text as the label universe expands? Third, how can
observations from previously classified texts enlarge the index? The following sections develop
these operations and then examine their reported classification and resource results.

4.2      Weighted Graph Indexing
GORAG maintains an undirected weighted graph 𝒢 𝑟 = (𝒱 𝑟 , ℰ 𝑟 , 𝒲 𝑟 ). Its node set contains
keyword nodes and label nodes. A keyword node represents an extracted word or short phrase.
A label node represents a target class. The representation places label alternatives inside the
same structure that stores their lexical associations. Individual support documents are used to
construct this representation; they are not defined as a third category of exemplar nodes in the
graph.
   A keyword–label edge is introduced when a keyword occurs in a text associated with that
label. Repeated occurrences across texts contribute to the edge weight. A keyword shared by sev-
eral classes can therefore have several label neighbors, with a different cost for each association.
Query retrieval will use these costs when choosing connections between mapped keywords. The
graph does not encode a fixed rule that every occurrence of a keyword implies the same class.
   This representation separates the unit used to store evidence from the unit used to make the
final prediction. The graph stores keyword–label associations. The language model receives the
original query text as well as the retrieved alternatives and their descriptive information. The
model can use syntactic and contextual information from the whole query even when retrieval
has operated on a smaller collection of keywords. The keyword-only ablation examines the

and phrases of fewer than three words. Let 𝒯≤𝑟 denote the corpus seen so far, and let df(𝑣) be

Here count(𝑣, 𝑡) is the occurrence count of 𝑣 in 𝑡, and |𝑡| is text length. The expression combines

costs.
    A statistical extraction score gives each retained term a numerical contribution before graph
retrieval. This contribution has a different role from the final language model’s confidence in
a label. The graph does not obtain a supervised probability of classification correctness from
this formula. Instead, the score determines which lexical units are indexed and how expensive
their associations will be in the retrieval structure. The evaluation of the full pipeline is therefore
needed to establish the effect on classification.

should be described as separate stages.

The complement converts a larger correlation score into a smaller contribution to connection
cost. Averaging makes the edge depend on all contributing observations rather than on one
occurrence. Offline observations use the supplied class of a support text; online observations
use a predicted class when new query keywords are inserted.
   An edge weight thus belongs to a particular keyword–label pair. It is not a global importance
weight assigned to the keyword irrespective of class. The same keyword may occur in several
label contexts, and the corresponding averages can differ. Retrieval uses the resulting cost struc-
ture together with connectivity. Replacing every cost by one preserves the graph’s adjacency
while removing this distinction, which is the purpose of the unit-weight ablation.
   The averaging rule also identifies the granularity at which evidence is combined. Texts are
not concatenated into one label description before the edge is scored. Each contributing text
supplies a correlation value and the edge records their mean complement. A later text can con-
tribute another occurrence to the associated pair. This design lets the index summarize recurrent
lexical associations without putting every support text into each classification prompt.


4.2.3    Merging label rounds

At each round, the graph created from newly supplied information is merged with the graph
accumulated from earlier rounds. The node and edge sets are unions. This operation retains the
label universe already introduced while adding nodes and associations for the new task state. It
differs from rebuilding a fresh graph containing only the most recently introduced labels, which
would remove access to earlier alternatives.

   Label bridges have a different evidential meaning from keyword–label edges. A keyword

structed index, with these distinct edge semantics, rather than as a sequence of independently

can select intermediate labels and keywords. The graph therefore determines the number of
candidate labels through the returned structure, rather than requiring the same number of labels
for all queries. A short query and a query containing several mutually distant indexed terms can
produce different retrieval structures.
   The distinction between terminals and intermediate nodes is central. Terminals must par-
ticipate because they represent the query’s mapped evidence. Intermediate nodes are included
because the selected connections pass through them. The final candidate labels are the label
nodes among these selected vertices. A label does not enter the candidate set merely because it
is present somewhere in the full index. This selective use of graph topology is how the retrieved
classification instruction can be smaller than the current task’s complete label universe.

                                                  6
    This terminal-connecting objective is related to the Steiner tree problem. In that problem, the
required terminals are a subset of graph vertices, and the solution may use additional vertices
to connect them. An ordinary minimum spanning tree instead spans all vertices of its input
graph. These objects play distinct roles in GORAG’s procedure. Describing every intermediate
structure as an exact optimum for the original terminal problem would obscure which vertices
are required and which connections have been chosen by the heuristic.


4.3.1    Tree and auxiliary-graph operations

GORAG uses a greedy terminal-connecting procedure based on Mehlhorn’s algorithm [4]. The
mapped keywords serve as terminals. An auxiliary graph 𝐻 represents connections between
terminals, with edge weights given by path costs. A minimum spanning tree of 𝐻 selects a
collection of terminal connections. Expanding these connections into their underlying paths
produces the graph structure used for candidate selection. The language model then receives the
labels encountered in this structure.
    The auxiliary tree and the returned structure have different vertex sets. The auxiliary tree
expresses connections among the terminals. Their expanded paths can also contain keyword and
label nodes that were not terminals. These intermediate nodes provide the connection between
the query’s lexical evidence and the candidate classes. The terminal set changes from query to
query, while the costs reflect the graph accumulated at the current round.
    The retrieval procedure favors a connected explanation of the mapped keywords over inde-
pendently selecting a fixed number of labels for each keyword. A label may be included because
it connects several terms, and an additional keyword node may connect terms that have no direct
edge. The returned structure can therefore express joint evidence that would be lost if each ter-
minal were treated as an independent lookup. Its label intersection is the compact output used
by classification.

object; the label intersection is the interface needed by the classifier. Supporting keywords and
label descriptions then provide additional context for these alternatives.
    The adaptive property concerns candidate selection after the query has been mapped. It

4.4.1    Computational organization

The graph separates work performed at a label update from work performed for each query. Of-
fline indexing processes the supplied texts, creates or updates keyword associations, generates
label information when available, and merges the round’s graph. The cross-round label bridges
introduce interactions between the newly indexed and earlier label regions. In the source’s ab-
stract operation count, construction is expressed as

The two terms account for label merging and keyword–text processing. This count treats the
associated text-processing and graph operations at the granularity used in that analysis. The
number of tokens processed by a language-model call depends on the prompt and generated
output, so the empirical token study supplies a separate measurement of model-facing work.
   Per-query processing maps the extracted terms to the existing graph, obtains a connecting
structure, builds the classification prompt, and inserts new terms after prediction. The index
state can therefore grow during one round as well as between label rounds. Graph memory
and prompt length measure different consequences of that growth. A larger stored index can
provide more candidate associations while a query still receives only the labels selected by its
own retrieval structure. The resource experiments report these two quantities separately.



4.5     Experimental Design
The published study evaluates CAD, WOS, and IFS-Rel. CAD contains social media posts an-
notated for contextual abuse [5]. WOS contains academic texts associated with research-area
labels [6]. IFS-Rel supplies relation-classification examples derived from news text in an in-
cremental few-shot benchmark [2]. These datasets exercise different label vocabularies and text
lengths within the dynamic classification setting.

4.5.1    Compared methods and controls

The study compares six baselines. Entailment constructs text–label entailment pairs and fine-
tunes a classifier [2]. NaiveRAG retrieves text chunks from the indexed support information. Re-
trieved context is compressed by LongLLMLingua before classification [7]. GraphRAG, Ligh-
tRAG, and HippoRAG2 supply graph-based retrieval alternatives [8–10]. Their classification
results are measurements of the adaptations used in this study.
   Entailment uses RoBERTa-large for five training epochs, a batch size of 16, a learning rate of
10−6 , and Adam. LongLLMLingua is evaluated with compression rates of 0.75, 0.8, and 0.85,
with 0.8 selected in the reported comparison. GraphRAG and LightRAG use local search. The
source uses the nano-graphrag implementation for GraphRAG and NaiveRAG and the other
baselines’ oﬀicial implementations. These choices identify the systems that produced the re-
ported results.
   The baseline collection tests several ways of allocating external context. NaiveRAG selects
passages. LongLLMLingua changes which tokens remain in that context. The graph base-
lines select graph-associated information. GORAG explicitly selects labels through a connec-
tion structure and expands its lexical index online. These differences motivate the comparison,
while the ablations isolate changes within GORAG’s own pipeline more directly.

4.7     Ablations and Resource Use

The WOS ablation study uses a one-shot Qwen2.5-7B setting. The offline variant disables online
indexing. The unit variant assigns cost one to every graph edge. The offline-and-unit variant
removes both features. The keyword variant uses the extracted keywords in place of the complete
query text for classification. These variants change specific inputs or index operations while
retaining GORAG’s overall classification task.

   In the ablation table, the full method reports 0.4862, 0.4649, 0.4814, and 0.4210 across
rounds. The offline variant reports 0.3063, 0.2302, 0.2455, and 0.2156. The unit variant reports
0.4706, 0.4394, 0.4407, and 0.3899. Under this ablation protocol, removing online insertion
has a larger observed effect than replacing the weighted graph with unit costs. This comparison
concerns the variants reported together in that table.

   The offline-and-unit variant reports 0.2979, 0.2287, 0.2645, and 0.2249. Its third- and fourth-
round values exceed those of the offline variant. The effects of removing these components
are therefore not strictly additive across rounds. The keyword variant reports 0.4746, 0.4606,
0.4455, and 0.4030, below the full method in each displayed column. The full query provides
information useful to the classifier in these experiments even though keywords determine the
retrieval terminals.

   The full-method row of this ablation table differs from the full-method row of the main WOS
table. They are retained as separate reported result series. Component comparisons above use
only the ablation table’s full-method row. Using a main-table value as the control for an ablation
value would introduce an unexplained change of result series.

4.8           Zero-shot and Round Generalization

The zero-shot IFS-Rel experiment supplies label names and language-model-generated descrip-
tions without annotated support texts. GORAG extracts keywords from these descriptions to
initialize its graph. The experiment consequently tests whether description-derived associations
can support candidate selection and subsequent classification. It does not measure a classifier
with no external label information.
        GORAG reports zero-shot accuracies of 0.9328, 0.5406, 0.4375, and 0.6063. The direct
GPT-4o comparison reports 0.9219, 0.5109, 0.4063, and 0.5936. LongLLMLingua reports
0.9281, 0.5297, 0.4234, and 0.5806. The graph-based comparisons in the same table are lower
under this initialization protocol. These values support the use of label descriptions as an initial
retrieval source for this experiment.
        The zero-shot result also illustrates why support size is not the only determinant of graph
content. A graph can be initialized from label descriptions, support texts, or a combination
allowed by the protocol. The few-shot results and zero-shot results use different available infor-

4.9     Discussion and Chapter Summary

GORAG places structure between the observation of text and the construction of a language
model’s classification instruction. Keywords connect the current text to an accumulated graph.
Edge costs and terminal connections select a subset of label alternatives. The model then classi-
fies the original text with these alternatives and their representative information. Structure serves
as a task-specific evidence-selection mechanism.
   The online component changes the source of that evidence. Support examples establish su-
pervised keyword–label associations. Subsequent predictions provide labels for newly observed
query keywords, allowing the index to cover terms absent from the support sample. The offline
ablation measures the contribution of this expansion under the evaluated conditions. Its bene-

                                                 18
fit is attached to a procedure whose state depends on earlier predictions, so the availability and
ordering of query observations are part of the evaluation setting.
    The graph’s paths provide a trace of the index connections used for retrieval. They can
reveal which keywords and labels were linked by the selected structure. This trace explains the
provenance of candidate selection in the constructed graph. The final classifier still receives text
and makes a language-model prediction; the retrieved path is an external evidence object rather
than an observation of the model’s internal computation.
    Several conditions bound the interpretation of the chapter’s evidence. Keyword extraction
determines which parts of a query can become terminals. Sparse support data and limited label
descriptions determine initial coverage. Predicted-label insertion can add incorrect associations.
The accuracy tables use exact label matching and different backbones for different datasets. Each
condition identifies a concrete component or evaluation choice that affects the reported classifi-
cation result.
    Within these conditions, the study shows how a task graph can reduce the label-selection
burden placed on a language model and maintain lexical evidence as the task evolves. The
contribution differs from KGLink’s use of an existing knowledge graph to enrich table repre-
sentations. Here the structure is built and updated from task data, and its immediate output
is a query-specific label set. The next chapter turns from choosing among labels to selecting
connected textual facts for an open-ended answer. That change requires a retrieval objective
that accounts for the relevance and connection cost of evidence beyond a fixed classification
vocabulary.
