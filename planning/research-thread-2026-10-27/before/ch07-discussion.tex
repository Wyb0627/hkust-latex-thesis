\chapter{Discussion}
\label{ch:discussion}

The four methods use relationships to make different evidence decisions. KGLink selects external descriptions for table columns, GORAG retrieves labels from an evolving index, AGRAG collects connected facts and passages, and MGRAG matches multimodal evidence and guides its processing. We compare when these decisions occur, how their errors propagate, and what they imply for answer quality and computation.

\section{Where Structure Enters the Pipeline}
\label{sec:discussion:pipeline}
KGLink filters linked entities before the encoder reads the table. Its graph processing determines which candidate types and feature descriptions enter the model, while supervised training learns how those descriptions correspond to annotation labels.

GORAG selects candidate labels before classification. Since predicted keyword--label associations are inserted into the index, one prediction can change the evidence retrieved for a later query.

AGRAG selects a connected subgraph for each query from a reusable corpus graph. Its hybrid retriever adds passages containing context absent from the selected relations.

\begin{samepage}
MGRAG makes query dependence part of graph construction. Matching controls whether another chunk is processed, and graph features determine which cached token states receive recomputation priority.\par
\end{samepage}

\section{Static, Online, and Query-dependent Structures}
\label{sec:discussion:adaptation}
KGLink reuses an external knowledge graph and adapts evidence selection to each table. Learning changes how the model uses the selected descriptions; it does not rebuild the source graph.

GORAG updates a task index as labels and text arrive. Associations from earlier predictions become available to later queries, so classification performance depends on the sequence of index states.

AGRAG prepares the corpus graph once, then changes query anchors, node influence, edge costs, and subgraph selection for each question. This amortizes graph preparation across repeated queries.

MGRAG extracts facts for each query as it consumes ranked chunks. Matching can stop construction before the full list is processed, but extraction and matching remain part of the query-time workload.

These alternatives correspond to different workloads. An existing knowledge graph is useful when entities and their external descriptions are available. Online indexing fits tasks whose label evidence evolves over a sequence. A reusable corpus graph supports repeated queries over shared text. Query-specific construction targets the evidence requirements of an individual multimodal question.

\section{Evidence Quality and Computational Cost}
\label{sec:discussion:cost}
The relevant quality criterion follows the task. A column representation must support the expected type label. Classification retrieval must retain the correct candidate label. Generation requires both sufficient answer coverage and support for the claims produced. Cache reuse must preserve answer quality while reducing processing cost.

A shared metric label can also conceal a different assessment rule. GORAG's accuracy requires the predicted class to match the gold label. AGRAG's QA accuracy uses model judgments scored 0, 0.5, or 1, while its classification accuracy uses label correctness. Its source-defined ROUGE-L quantity divides longest-common-subsequence length by generated-answer length. MGRAG reports answer accuracy alongside semantic similarity and lexical overlap.\par

The AGRAG ablations show why coverage and faithfulness must be considered together. Without hybrid passages, the generator can produce supported claims while omitting required information. Graph connectivity helps organize facts, while passages preserve context that extraction or subgraph selection can omit.

MGRAG separates evidence retrieval from reuse of its computation. Cache comparisons measure combined retrieval and serving choices. Inverse ablations test additions within one retrieval pipeline, where improved answer quality can require extra runtime.

Indexing and query costs also need to remain separate. KGLink reports preprocessing and model-processing costs for annotation. GORAG reports the resource demands of its evolving index and retrieval. AGRAG separates corpus indexing from querying. MGRAG reports construction, matching, answer-generation, and end-to-end costs.

\section{Information Preservation and Semantic Granularity}
\label{sec:discussion:preservation}
The hyper-relational study in Chapter~\ref{ch:background} supplies another perspective on structural representations. A main triple and its qualifiers express different aspects of a fact. Decomposing that representation can retain some relationships while losing the association that gives them their meaning. The study examines this issue through decomposition methods, qualifier capture, graph reception, and link-prediction results.

A related design question appears in each core chapter. KGLink must translate graph-derived type descriptions into the annotation task's vocabulary. GORAG associates words with labels whose relevance depends on the classification task. AGRAG selects a graph serialization while retaining a passage channel for information absent from that serialization. MGRAG matches relations to paths that can express a corresponding meaning through a different topology. Each method specifies an evidence unit and a way to relate that unit to the task.

A column vector, candidate label, graph fact, path, and source passage preserve different information. Paths expose intermediate relations, while passages and images retain details that may disappear during extraction. Moving between these representations changes what the next stage must infer.

A useful structure must preserve the relationships needed for the task. Connectivity identifies available links, semantic matching checks their correspondence to a query, and supervision determines the required annotation category. The hyper-relational study examines how graph transformation can alter these relationships before prediction.

\section{Error Propagation Across Structural Decisions}
\label{sec:discussion:unit}
The location of a structural decision affects how an error can propagate. An incorrect KGLink entity link changes the descriptions offered to the encoder for a table. In GORAG, an incorrect predicted label can become an association available to later queries. AGRAG reuses a corpus graph, so an extracted relation can influence several query-specific selections. MGRAG constructs a new graph for each query, but a mistaken accepted match can end construction before later chunks are examined.

Feedback can target these error sources directly. Entity disambiguation can revise cell links, online correction can revise inserted associations, source verification can check extracted relations, and matching diagnosis can inspect entity alignment and path choices. Chapter~\ref{ch:conclusion} develops these directions.

\section{Limitations and Open Questions}
\label{sec:discussion:limitations}
KGLink depends on the coverage and vocabulary of the external graph. Its no-linkage analysis tests tables without retrieved KG evidence, while broader use also depends on graph language, update state, and alignment with the target labels.

GORAG can retain errors through prediction-derived index updates. Longer streams and different patterns of label evolution remain untested.

AGRAG and MGRAG depend on extracted relations, and MGRAG additionally depends on caption-based image ranking. Missing or inaccurate facts can prevent the generator from receiving relevant evidence. Model-assessed QA metrics also depend on the evaluator and its assessment rules.

AGRAG's 2-approximation statement applies to its initial terminal-connecting tree. MGRAG's threshold condition describes accepted path similarities. Neither characterizes the answer quality of the full retrieval and generation pipeline.
