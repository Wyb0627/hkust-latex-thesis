\chapter{Background and Related Work}
\label{ch:background}

This chapter reviews knowledge structures for language-model understanding and reasoning. We first introduce how explicit relationships organize external information and how this information enters a language model. We then review knowledge-enhanced table annotation, few-shot adaptation, and graph-based retrieval. Multimodal retrieval and context processing extend this direction to text and images. Section~\ref{sec:background:hyperkg} presents our study of information preservation in hyper-relational knowledge graphs.

\section{Knowledge Structures for Language Models}
\label{sec:background:knowledge-models}

A knowledge graph represents entities and their relationships explicitly~\cite{bg-ji2022kg}. A conventional relational fact is a triple $(s,r,o)$, where $s$ is a subject entity, $r$ a relation, and $o$ an object entity. These triples form a directed graph with entities as nodes and relations as labeled edges. For example, an occupation relation can connect a person to a profession, supplying information absent from a table that contains only names. Resources such as Wikidata make these statements accessible beyond the document in which an entity is mentioned~\cite{bg-wikidata}.

The relationships needed by a task can also be constructed from its own data. HippoRAG extracts relational triples from passages to build a graph for retrieval~\cite{bg-hipporag}. A classification graph can instead connect keywords to labels according to their associations in task examples, as in GORAG~\cite{bg-gorag}. The meaning of an edge therefore depends on how it is constructed. An extracted factual relation describes the source content, while a keyword-label edge records an association used for classification. AGRAG and MGRAG further link extracted facts to source chunks, allowing retrieval to return both structured relationships and the original text or images~\cite{bg-agrag,bg-mgrag}.

Accessing an existing graph requires identifying which nodes correspond to the input. Entity linking maps a mention in a table cell or passage to an indexed entity. Since a name can refer to several entities, its surrounding context helps disambiguate the candidates. BLINK retrieves candidate entities using dense representations of mention contexts and entity descriptions, then reranks them with a cross-encoder~\cite{bg-wu2020blink}. KGLink uses connections between table columns to filter linked candidates~\cite{bg-kglink}. When a graph is built from source documents, entity resolution also determines whether mentions in different passages share a node. AGRAG adds synonym edges between similar entity strings to connect expressions indexed as separate nodes~\cite{bg-agrag}.

Once the input is mapped to the graph, neighborhoods, paths, and subgraphs provide different ways to select information. A neighborhood supplies facts around a linked entity. A path can connect several facts through intermediate entities, while a subgraph can collect multiple related paths. Think-on-Graph uses a language model to explore entities and relations iteratively and select reasoning paths from an existing KG~\cite{bg-sun2024tog}. For tasks requiring several supporting facts, the retrieval decision must account for their connections as well as their individual relevance. Source links provide access to details that remain in the original passages after relation extraction~\cite{bg-agrag}.

Selected knowledge can enter a language model through learned representations. Transformer attention computes contextual token representations, which BERT learns through bidirectional pre-training~\cite{bg-transformer,bg-bert}. KnowBERT retrieves entity embeddings through an integrated entity linker and combines them with contextual word representations through word-to-entity attention~\cite{bg-peters2019knowbert}. KEPLER jointly optimizes knowledge-embedding and language-modeling objectives using encoded entity descriptions~\cite{bg-wang2021kepler}. These approaches incorporate knowledge during representation learning. Graph structure can also enter through a learned graph encoder and projection module, as in Graph Neural Prompting~\cite{bg-tian2024gnp}.

Knowledge can also be expressed as additional input text. K-BERT injects KG triples into sentences and controls their interaction through soft positions and an attention visibility matrix~\cite{bg-liu2020kbert}. In a prompting pipeline, selected graph facts become context for a generative language model, as studied by KnowGPT~\cite{lit-zhang2024knowgpt}. The graph used for selection can therefore differ from the input received by the model. A graph may index entities and relations, while the model reads their descriptions, serialized triples, or associated source passages. This conversion determines which relationships and source details are available for prediction.

How knowledge enters the model also affects task adaptation. Supervised fine-tuning updates model parameters using labeled examples. In-context learning supplies task instructions or examples in the input without gradient updates for that task~\cite{lit-brown2020language}. Retrieval selects external evidence for the current input~\cite{bg-rag}. An index can incorporate new documents, labels, or associations, changing the available context while the prediction model remains fixed. GORAG uses supplied labels to initialize its graph and subsequent predictions to associate newly observed keywords with classes~\cite{bg-gorag}. Its updates change the retrieval source used by later queries.

For table annotation, graph coverage and differences between graph descriptions and target labels affect how retrieved knowledge can be used~\cite{bg-kglink}. The next section reviews this setting.

\section{Knowledge-enhanced Table Understanding}
\label{sec:background:tables}

Column-type annotation assigns semantic labels to table columns. Similar values can require different labels under different annotation vocabularies. A column of people may be labeled Name or assigned an occupation category. Surrounding columns and external facts can help determine the intended type.

WebTables demonstrated that relational tables extracted from the Web form a large collection of small databases and that corpus-wide schema statistics support table search and schema applications~\cite{lit-cafarella2008webtables}. This setting motivates methods that recover semantics from cell values, surrounding columns, and other tables when a target table has limited metadata.

Sherlock trains a neural type detector from statistical properties, character distributions, word embeddings, and paragraph vectors~\cite{bg-sherlock}. Sato adds topic features and structured prediction to model which column types occur together~\cite{bg-sato}. The two approaches differ in whether table context contributes to the prediction.

Doduo serializes multiple columns for a pre-trained language model and learns column-type and column-property annotations from their contextual representations~\cite{bg-doduo}. Self-attention lets a column representation depend on values in other columns, subject to the input-length limit.

Table pre-training can encode additional structural information. TURL learns contextual representations of relational tables through self-supervised pre-training~\cite{lit-deng2022turl}. TAPAS augments a language model with table-aware inputs and learns to answer questions through cell selection and aggregation~\cite{lit-herzig2020tapas}. TableFormer introduces learned attention biases for table structure and table--text alignment while addressing sensitivity to row and column order~\cite{lit-yang2022tableformer}. These designs show how serialization, structural biases, and pre-training tasks affect the table information available to a predictor.

Knowledge-based methods obtain evidence through a different route. HNN combines learned table features with knowledge-base lookup and inter-column semantics~\cite{bg-hnn}. A knowledge resource can identify a relation between mentioned objects that the table's strings do not explain. RECA uses related tables as an additional contextual source~\cite{bg-reca}. These approaches extend the information available within the target table through external semantic facts or evidence from other tables. Their retrieval units and preparation costs differ accordingly.

ColNet combines knowledge-base-derived supervision with convolutional representations of cell and column semantics~\cite{lit-chen2019colnet}. TCN models contextual information within and across Web tables through a table convolutional network~\cite{lit-wang2021tcn}. Together with RECA, these approaches illustrate different uses of external context, from knowledge-base concepts to relationships among tables. KGLink instead selects graph-derived descriptions for an encoder that learns the target annotation vocabulary.

KGLink retrieves candidate entities for cell mentions and filters them through connections between columns~\cite{bg-kglink}. Candidate-type text and a separate KG feature sequence enrich the column representation. A contextual type-representation objective learns the correspondence between graph descriptions and annotation labels. Chapter~\ref{ch:kglink} presents the method and experiments.

These methods obtain context from different sources. Statistical features summarize column contents, contextual encoders model values jointly, RECA retrieves related tables, and knowledge-based methods retrieve external facts. Their coverage determines which ambiguities they can resolve.

\section{Few-shot Adaptation and Evolving Label Sets}
\label{sec:background:fewshot}

Few-shot learning studies prediction from limited labeled examples, often using experience from related tasks to support adaptation~\cite{lit-wang2020generalizing}. The support set provides examples of the current classes, while the query set tests the resulting decisions. A method must specify which information is learned beforehand and which information becomes available for a new task.

Metric-based methods organize support information in a learned representation space. Matching Networks use an attention-based prediction over support examples, while Prototypical Networks compare query representations with class prototypes~\cite{lit-vinyals2016matching,lit-snell2017prototypical}. Relation Networks learn a comparison function between examples~\cite{lit-sung2018learning}. Model-agnostic meta-learning instead learns an initialization that supports adaptation through a small number of gradient updates~\cite{lit-finn2017model}. The learned metric, comparison function, and initialization provide different mechanisms for using a small support set.

An expanding label set adds the need to retain earlier categories. Dynamic Few-Shot Visual Learning studies recognizing novel categories while preserving base categories, and Attention Attractor Networks regularize the addition of new classifier weights in incremental few-shot learning~\cite{lit-gidaris2018dynamic,lit-ren2019incremental}. These visual-learning settings establish related adaptation problems; incremental few-shot text classification introduces successive rounds of text labels and limited examples~\cite{gorag-xia-etal-2021-incremental}.

Large language models introduce another adaptation interface. GPT-3 demonstrates prediction from task descriptions and examples supplied in the prompt, without gradient updates for the demonstrated task~\cite{lit-brown2020language}. GORAG uses a language model for this prediction role, but maintains keyword--label associations in an external graph. Its online updates change which label evidence is retrieved for subsequent queries.

\section{Retrieval-augmented Generation}
\label{sec:background:rag}

Retrieval-augmented generation conditions a generative model on information selected from an external collection~\cite{bg-rag}. A retrieval stage maps the query to indexed evidence, and a generation stage uses the evidence to produce an answer. The external collection supplies evidence at prediction time. Updating the collection or its retrieval rule changes the generator's context even when its parameters stay fixed.

Retrieval can also participate in model training. REALM trains a language model with a latent knowledge retriever, RETRO conditions generation on chunks retrieved from a large text collection, and Atlas studies few-shot knowledge-intensive tasks with a pre-trained retrieval-augmented model~\cite{lit-guu2020retrieval,lit-borgeaud2022improving,lit-izacard2023atlas}. These systems make the retrieval source part of the model's information supply, while differing in their training objectives and task adaptation.

A passage-based RAG pipeline divides a corpus into chunks, indexes them, and concatenates the retrieved chunks with the query. Small chunks can separate a fact from its explanation. Large chunks preserve more context but consume more input tokens. Overlap retains information across chunk boundaries at the cost of repeating some text.

Sparse retrieval scores lexical evidence. BM25 combines within-document term frequency with corpus frequency and document-length normalization~\cite{bg-bm25}. It distinguishes a query term that occurs widely from one that is concentrated in fewer indexed items. Dense retrieval instead represents queries and passages as vectors and scores their correspondence in a learned space. Dense Passage Retrieval uses a dual-encoder framework with separate question and passage encoders~\cite{bg-dpr}. The two representations provide different signals, so hybrid retrieval can select context using both lexical overlap and embedding similarity.

Retrieval need not compress each passage into a single vector. ColBERT independently encodes query and passage tokens, then uses a late-interaction operation to score fine-grained matches~\cite{lit-khattab2020colbert}. HyDE addresses retrieval without relevance labels by generating a hypothetical document and encoding it as a search representation~\cite{lit-gao2023hyde}. The generated document guides retrieval; the retrieved source documents supply the evidence used downstream. These methods change the representation used to find context without requiring a graph index.

For a query $q$ and indexed evidence item $e$, write the retrieval score abstractly as $s(q,e)$. A conventional fixed-budget result contains the highest-scoring $k$ items. Evidence is scored at the chosen item granularity, and the retrieval cutoff controls how many items are returned. A graph-based system can alter either assumption. It can score relationships as well as items, or determine the context by a structural condition such as connecting query anchors. The selected nodes and relationships are then serialized as context for the language model.

Retrieval evaluation measures whether the selected context contains supporting evidence. Generation evaluation measures the resulting answer through correctness, reference overlap, or model-based assessment. An answer improvement can arise from selecting better evidence, organizing the context, or using it more effectively.

Question-answering benchmarks expose different evidence requirements. Natural Questions contains naturally occurring search queries with long and short answer annotations on Wikipedia pages, while TriviaQA pairs trivia questions with independently gathered evidence documents~\cite{lit-kwiatkowski2019natural,lit-joshi2017triviaqa}. MuSiQue constructs multihop questions by composing connected single-hop questions so that one reasoning step depends on information from another~\cite{lit-trivedi2022musique}. These collections help distinguish locating supporting text from reading or generating an answer from it.

Complex questions can require retrieval to change as reasoning proceeds. IRCoT interleaves retrieval with generated intermediate reasoning steps, using those steps to search for further evidence~\cite{lit-trivedi2022interleaving}. This iterative approach obtains additional context through successive retrieval decisions. Graph-based retrieval instead makes extracted relationships available within the index, where several supporting facts can be selected through connected paths or propagation.

An evolving collection adds a maintenance problem. Newly available documents, examples, or labels must enter the index before retrieval can use them. Updating stored evidence can involve new embeddings, new graph nodes, changed edge weights, or derived summaries. The information supplied by an update also matters. A labeled support example carries a provided class, while a query processed online may carry only a model prediction. GORAG makes this distinction part of its dynamic classification protocol~\cite{bg-gorag}. Its index expands as observations arrive, and retrieval uses the graph state available at the current prediction.

Retrieving more passages can increase both answer coverage and model-processing cost. The retrieval budget therefore affects the information available to the generator even when the corpus and model remain fixed.

A larger context window does not ensure that all supplied evidence is used equally well. Lost in the Middle shows that answer performance can depend strongly on where relevant information occurs in a long input~\cite{lit-liu2024lost}. Evidence selection and organization therefore remain relevant even when the model can accept additional passages.

The indexed object can differ from the retrieved context. A document can contribute several graph facts, a traversal can return candidate labels, and a prompt can combine selected relationships with source passages. Graph retrieval makes these connections available during evidence selection.

\section{Graph-based Evidence Retrieval}
\label{sec:background:graph-retrieval}

Graph indexes connect entities, passages, labels, and other evidence items through extracted facts, shared mentions, or semantic similarity. Retrieval selects the nodes and connections relevant to the current query.

GraphRAG builds an entity graph and community summaries for query-focused summarization~\cite{bg-graphrag}. Community summaries provide a retrieval unit above individual passages and support questions about broader corpus themes.

HippoRAG combines language-model extraction, a knowledge graph, and personalized PageRank~\cite{bg-hipporag}. Query entities seed propagation through the graph, producing a ranking of related evidence. This ranking does not require all selected nodes to belong to one terminal-connecting structure.

LightRAG combines graph and vector representations, low- and high-level retrieval, and incremental index updates~\cite{bg-lightrag}. Its retrieval modes select specific entity information and broader relational or conceptual information.

KnowGPT studies knowledge-graph-based prompting by extracting useful knowledge and constructing context-aware prompts~\cite{lit-zhang2024knowgpt}. It makes graph knowledge available through the prompt supplied to a language model. This connects the retrieval decision to how the selected information is presented, complementing methods that rank nodes, return source passages, or summarize graph communities.

Personalized propagation ranks evidence by influence from query anchors. Terminal-connecting retrieval instead selects paths that include a specified set of nodes, admitting intermediate nodes when needed. The former locates relevant graph regions; the latter constructs connections among required evidence items.

The retrieved graph must be converted into model input. Entity retrieval requires finding associated source passages. Path retrieval requires serializing entities and relations. Community retrieval can return derived summaries. These choices determine which original details and relationships remain available to generation.

Our research moves from retrieving candidate classes to retrieving facts that support an answer. GORAG constructs a task graph and retrieves labels by connecting keywords extracted from the query~\cite{bg-gorag}. AGRAG selects connected textual evidence while considering node influence and edge cost~\cite{bg-agrag}. MGRAG constructs query-related multimodal graphs and matches query relations to semantic paths~\cite{bg-mgrag}. A set of highly ranked nodes need not contain paths connecting the requested facts, while intermediate nodes can supply useful relationships even when their direct query similarity is lower.

Passage nodes link extracted relations to their original wording. Combining graph serialization with source chunks gives the generator both connected facts and surrounding context. AGRAG uses this combination for text, and MGRAG retains source chunks containing the original images.

\subsection{Reasoning structures and source evidence}

Explicit structure also appears in generated reasoning. Chain-of-thought prompting supplies intermediate reasoning demonstrations, and Zero-shot-CoT uses a reasoning instruction without task-specific demonstrations~\cite{lit-wei2022chain,lit-kojima2022large}. Plan-and-Solve prompting first develops a plan and then carries out its subtasks~\cite{lit-wang2023plan}. These approaches organize how a model produces intermediate steps.

Tree of Thoughts searches over alternative intermediate thoughts, while Graph of Thoughts allows dependencies and combinations among generated information units~\cite{lit-yao2024tree,lit-besta2024graph}. Their nodes represent model-generated reasoning states. In an evidence graph, nodes and edges instead describe information extracted or indexed from task data. Combining a reasoning structure with retrieved facts therefore requires tracking the source of each information item.

The NLGraph study evaluates graph problems expressed in natural language and finds that language-model performance depends on problem complexity and graph presentation~\cite{lit-wang2023can}. This motivates specifying which structural operations are performed by graph algorithms and which decisions are left to a language model. In our retrieval pipelines, graph construction and selection define the evidence passed to the final predictor.

\section{Multimodal Retrieval and Context Serving}
\label{sec:background:multimodal}

Multimodal question answering requires evidence represented in more than one modality. MultiModalQA includes questions over text, tables, and images and studies combinations of evidence across them~\cite{bg-mmqa}. The evidence needed for a question can occur in different source objects. A relationship stated in text may identify the image whose visual content contains the answer. Retrieval must therefore consider both the relevance of individual objects and the relationship connecting them to the question.

The VQA task asks for an answer to a natural-language question about an image, making visual relevance depend on the question~\cite{lit-antol2015vqa}. OK-VQA adds questions that require knowledge beyond the image content~\cite{lit-marino2019okvqa}. MultiModalQA extends the evidence requirement to reasoning across source modalities. The distinction matters for retrieval because a visually informative image can still lack the particular detail or relationship requested by the question.

Vision--language pre-training supplies several ways to align the modalities. ViLBERT uses interacting visual and textual streams, while BLIP combines understanding and generation objectives with caption bootstrapping~\cite{lit-lu2019vilbert,lit-li2022blip}. BLIP-2 connects frozen image and language models through a trainable querying component~\cite{lit-li2023blip2}. These architectures determine how visual content becomes accessible to language-based prediction.

Flamingo supports few-shot prediction with interleaved visual and textual inputs~\cite{lit-alayrac2022flamingo}. LLaVA studies visual instruction tuning, and InstructBLIP introduces instruction-aware visual feature extraction~\cite{lit-liu2023llava,lit-dai2023instructblip}. Such models can condition their processing on a task instruction, but a retrieval pipeline must additionally identify which source objects contain the supporting evidence. MGRAG uses query-aware graph construction to organize relationships among those objects.

Images can be ranked through captions or visual embeddings. Captions expose selected visual content in a text embedding space, while the original images preserve details for multimodal generation. MGRAG ranks images through captions and supplies selected original chunks to the answering model~\cite{bg-mgrag}.

MRAMG-Bench studies retrieval-augmented generation in which answers can combine text and images~\cite{bg-mramg}. Its multimodal output requirement adds another distinction between finding supporting evidence and presenting the response. The MGRAG evaluation uses six MRAMG subsets together with MMQA. Chapter~\ref{ch:mgrag} specifies the retrieval and answer-assessment protocol used for these datasets.

Once evidence is retrieved, the system must process it as model context. In an autoregressive Transformer, the prefill stage computes representations for the supplied input, and decoding generates answer tokens. Key and value tensors from processed input positions can be cached for later attention computation~\cite{bg-transformer,bg-cacheblend}. Reusing these tensors concerns the computation associated with selected evidence. It is a separate decision from choosing which evidence belongs in the context.

Attention computation, cache retention, and cache recomputation address different costs. FlashAttention reduces memory traffic through an IO-aware implementation of exact attention~\cite{lit-dao2022flashattention}. H2O retains a combination of recent and heavily attended tokens, while Scissorhands exploits persistent token importance to compress the KV cache~\cite{lit-zhang2023h2o,lit-liu2023scissorhands}. These retention policies decide which states remain available; selective recomputation decides which available states to refresh when the context changes.

CacheGen addresses the storage and transfer of context caches through compression and streaming~\cite{bg-cachegen}. The relevant resource includes the cost of fetching cached tensors as well as computing context representations. CacheBlend studies combining precomputed caches for several chunks by selectively recomputing part of their key and value states~\cite{bg-cacheblend}. Its motivation includes interactions between chunks that were not present when their caches were independently computed. These methods place context serving within the evidence pipeline, where retrieval order and the assembled input can affect the computation required for generation.

MGRAG supplements attention-based recomputation scores with features of the retrieved graph~\cite{bg-mgrag}. The graph therefore guides both context selection and the computation reused when that context is processed.

\section{Structural Information in Hyper-relational Knowledge Graphs}
\label{sec:background:hyperkg}

This section presents our work \emph{Understanding the Embedding Models on Hyper-relational Knowledge Graph}, published at CIKM 2025~\cite{bg-hyperkg}. It examines how graph representations and embedding architectures preserve information used for link prediction. Transforming source information into a graph determines which relationships a downstream model can access. The study analyzes this representation problem through fact decomposition, qualifier capture, and graph reception.

\subsection{Facts, Qualifiers, and Decomposition}

A hyper-relational fact extends a main triple with a set of qualifier pairs,
\begin{equation}
F=\left(s,r,o,\mathcal{Q}\right),\qquad
\mathcal{Q}=\{(qr_i,qe_i)\}_{i=1}^{n}.
\label{eq:background:hyper-fact}
\end{equation}
Here $F$ is the fact, $(s,r,o)$ is its subject--relation--object main triple, and $\mathcal Q$ contains $n$ qualifier pairs. In pair $i$, $qr_i$ is a qualifier relation and $qe_i$ its associated entity. Qualifiers attach information to a particular statement. For example, degree and major can distinguish two education statements about the same person. Their association with the intended main triple is part of the information represented by the fact. StarE retains the semantic roles of qualifiers and triples in message passing and introduces WD50K for hyper-relational link prediction~\cite{bg-stare}.

Related work represents facts with more than two participating entities in several ways. NaLP models the relatedness among role--value pairs, GETD extends tensor decomposition to n-ary relational knowledge bases, and RAM learns role-aware representations~\cite{lit-guan2019link,lit-liu2020generalizing,lit-liu2021role}. These representations expose the roles occupied by entities within a fact.

NeuInfer represents a primary triple together with auxiliary attribute--value descriptions and studies inference from complete or partial facts~\cite{lit-guan2020neuinfer}. HAHE combines global hypergraph structure with local sequential representations of hyper-relational facts~\cite{lit-luo2023hahe}. These designs motivate examining both information within a fact and information received from the wider graph, the two aspects studied below.

The CIKM study asks how much of an HKGE model's performance comes from its base KGE architecture and how much comes from specialized qualifier processing. It evaluates a data-level alternative to modifying the model. Three decomposition methods convert a hyper-relational fact into ordinary triples while retaining different information. Prune keeps only the main triple. Direct adds triples connecting the subject to qualifier entities through their qualifier relations. Hyper adds further relations whose names combine the main relation with each qualifier relation and connect the qualifier entity to the main object.

Figure~\ref{fig:background:decomposition} reproduces the original comparison, including database reification. The study distinguishes main-triple information, intra-qualifier information, and inter-qualifier information. A decomposition can retain qualifier entities and relation labels while changing how their association with the main fact is expressed. Database reification introduces auxiliary entities and relations, also changing the original main-triple topology. These differences determine which neighborhoods and paths an ordinary KGE model receives after conversion.

Qualifier associations matter when a subject participates in several facts with the same relation. For example, a degree qualifies a particular university attendance statement. Separate subject--degree and subject--university triples retain the entities but change how that association is represented. Hyper adds connections intended to preserve these associations. A qualifier integrator instead receives the main fact and its qualifier pairs together.

We compare conventional KGE models under these transformations with specialized HKGE models. Some GNN-based configurations obtain comparable scores on Cleaned JF17k and WD50k. Adding qualifier-derived edges changes the graph paths available to an encoder, so information preservation depends on both the transformed data and the model that processes it.

\subsection{Qualifier Capture and Graph Reception}

The analysis separates qualifier capture from graph reception. Qualifier capture concerns how the model represents qualifier pairs and their association with the main statement. Graph reception concerns how it receives information from the wider graph, including dependencies beyond one fact. Models operating on a fact in isolation have a different receptive field from graph encoders that propagate information across several hops. These properties are visible in the operations used to construct representations.

CompGCN jointly models entity and relation representations in a multi-relational graph~\cite{bg-compgcn}. NBFNet aggregates path information for link prediction~\cite{bg-nbfnet}. Their graph computations offer different ways to receive neighborhood and path information after decomposition. The CIKM analysis also identifies an information-compression issue when qualifier information is aggregated into fixed-size main-triple representations. Graph reception supplies wider context, while qualifier integration preserves information within each fact. The study evaluates designs that retain both sources for prediction.

FormerGNN combines a Transformer-based qualifier integrator operating on the original hyper-relational facts with a graph encoder operating on the pruned main-triple graph. The graph encoder generates a topology representation for the subject. The model concatenates this representation with representations of the main triple and qualifier pairs and passes them to a Transformer decoder. This organization supplies qualifier and graph information jointly to the prediction stage. In the reported configuration, HyperFormer provides the qualifier integrator and NBFNet provides the graph encoder~\cite{bg-hyperformer,bg-nbfnet}.

\section{Research Questions Emerging from the Background}
\label{sec:background:questions}

Knowledge-enhanced annotation motivates our first question about supplying missing context and learning its correspondence to labels. Dependence on existing graphs and supervised training then motivates graph construction from task data and adaptation through retrieval. Extending retrieval beyond classification introduces questions about connected evidence and answer coverage for text, and query-aware construction and semantic matching for multimodal sources. The following chapters investigate these questions.
