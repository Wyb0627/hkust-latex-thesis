\chapter{Adaptive Graph Retrieval for Dynamic Classification with GORAG}
\label{ch:gorag}

This chapter is based on \emph{GORAG: Graph-based Online Retrieval Augmented Generation for Dynamic Few-shot Social Media Text Classification}, published in the Proceedings of the ACM Web Conference 2026~\cite{gorag-paper}. We propose GORAG to construct and maintain a weighted graph of keyword--label associations from task data. Connected retrieval selects candidate labels for a large language model, and online insertion adds unseen terms after classification.

\section{Dynamic Few-shot Classification}
\label{sec:gorag:task}

KGLink uses an existing knowledge graph to enrich representations through supervised fine-tuning. For applications without a suitable graph or sufficient training data, we instead build a graph from the task's own examples and use a large language model for prediction. Retrieved labels and descriptions supply context, allowing new information to be incorporated without parameter fine-tuning. We study this approach in dynamic few-shot classification, where the target categories evolve as new examples arrive.

Dynamic classification must distinguish new categories from those introduced earlier. For example, an abuse classifier may initially recognize threatening language and later add identity insults. With few examples per class, the system must recognize the new category while retaining access to earlier labels.

Few-shot classification provides a small labeled support set for each class. In the dynamic setting, new classes arrive in successive rounds~\cite{gorag-xia-etal-2021-incremental}. The index must incorporate their examples while preserving evidence for the cumulative label set.

Adding more examples to the prompt can introduce irrelevant context as the label set grows. Passage retrieval alone also leaves the generator to choose among all labels. We instead retrieve a candidate label set for each query.

To select labels jointly from the query keywords, we represent keywords and labels in a weighted graph. A keyword can connect to several labels, with an edge cost for each association. Connecting several query keywords selects labels jointly from their neighborhoods.

GORAG also updates its index after classifying an unlabeled query. Keywords that were absent from the index can then become available to later queries. The predicted label associates the newly observed keywords with a class for subsequent retrieval. Support examples initialize the graph using their supplied labels.

GORAG combines weighted indexing, connected candidate-label retrieval, and online insertion. The following sections define these operations and evaluate their classification accuracy and resource costs.

\subsection{Rounds and information availability}
\label{sec:gorag:rounds}

Let $\mathcal{Y}_{\mathrm{new}}^r$ denote the labels introduced at round $r$. The current label universe is
\begin{equation}
\mathcal{Y}^r=\bigcup_{i=1}^{r}\mathcal{Y}_{\mathrm{new}}^i.
\label{eq:gorag:labels}
\end{equation}
Here $\mathcal Y^r$ is the union of the label sets $\mathcal Y_{\mathrm{new}}^i$ introduced in rounds $i=1,\ldots,r$. The few-shot support data provide $k$ annotated texts per class, with $k$ equal to 1, 5, or 10 in the main experiments. A query text $t$ must be assigned a label from $\mathcal{Y}^r$. The superscript $r$ identifies the current classification round.

Support texts carry supplied labels. Query texts become visible as the system processes them, and their predictions can be used for subsequent index updates. Corpus statistics used in keyword scoring refer to training and query texts seen so far. The online association nevertheless inherits prediction errors when the classifier chooses an incorrect label.

Semantic label names supply another source of information. Where names are available, GORAG uses a language model to generate representative descriptions or keywords for labels. These descriptions enter the classification context, and label-derived keywords can support graph initialization. The zero-shot experiment later in this chapter uses this source without any labeled examples.

\section{Weighted Graph Indexing}
\label{sec:gorag:indexing}

GORAG maintains an undirected weighted graph $\mathcal{G}^r=(\mathcal{V}^r,\mathcal{E}^r,\mathcal{W}^r)$. Here $\mathcal V^r$ and $\mathcal E^r$ are the node and edge sets, and $\mathcal W^r$ contains their edge costs. Its node set contains keyword nodes and label nodes. A keyword node represents an extracted word or short phrase. A label node represents a target class. Label nodes make candidate classes directly accessible through their keyword associations. Support documents contribute keyword--label associations to this representation.

A keyword--label edge is introduced when a keyword occurs in a text associated with that label. Repeated occurrences across texts contribute to the edge weight. A keyword shared by several classes can therefore have several label neighbors, with a different cost for each association. Query retrieval will use these costs when choosing connections between mapped keywords.

The graph stores keyword--label associations, while the classifier receives the original query, retrieved labels, and their descriptions. The full query retains syntax, word order, and discourse omitted by keyword extraction. The keyword-only ablation removes this full-text input.

\subsection{Keyword extraction and correlation scores}
\label{sec:gorag:keywords}

GORAG scores terms using normalized TF--IDF~\cite{gorag-tfidf}. Its extraction vocabulary includes words and phrases of fewer than three words. Let $\mathcal{T}_{\leq r}$ denote the corpus seen so far, and let $\operatorname{df}(v)$ be the number of its texts containing term $v$. The reported correlation score is
\begin{equation}
CS(v,t)=\frac{\operatorname{count}(v,t)}{|t|\log(|\mathcal{T}_{\leq r}|+1)}
\log\frac{|\mathcal{T}_{\leq r}|+1}{\operatorname{df}(v)+1}.
\label{eq:gorag:correlation}
\end{equation}
Here $CS(v,t)$ is the correlation score of term $v$ in text $t$, $\operatorname{count}(v,t)$ counts its occurrences, $|t|$ is the text length, $\operatorname{df}(v)$ counts the seen texts containing the term, and $\mathcal T_{\leq r}$ is the corpus observed by round $r$. The expression combines frequency within the text with frequency across the observed corpus. Its corpus term changes when additional texts are observed. Terms with $CS(v,t)>\tau$ are retained, with $\tau=0.5$ in the original study. The method uses the score both to select keywords and to calculate association costs.
% Verification issue G5: source reports CS>tau with tau=0.5; normalization/threshold needs author/publication confirmation. Do not silently rescale.

Short phrases preserve lexical combinations that unigram extraction would split. Only extracted terms can become retrieval terminals, although the classifier still receives the full query text.

\subsection{Keyword--label edge costs}
\label{sec:gorag:weights}

For keyword $v$ and label $y$, let $\mathcal{T}^{r,v,y}$ be the seen texts that contain $v$ and are associated with $y$. GORAG assigns the edge cost
\begin{equation}
w_{v,y}^r=\frac{\sum_{t_j\in\mathcal{T}^{r,v,y}}(1-CS(v,t_j))}{|\mathcal{T}^{r,v,y}|}.
\label{eq:gorag:weights}
\end{equation}
Here $w_{v,y}^r$ is the cost of the edge between keyword $v$ and label $y$, $\mathcal T^{r,v,y}$ is their associated set of seen texts, and $CS(v,t_j)$ is the correlation score in text $t_j$. Subtracting the correlation score from one gives stronger keyword associations lower connection costs. Averaging makes the edge depend on all contributing observations rather than on one occurrence. Offline observations use the supplied class of a support text; online observations use a predicted class when new query keywords are inserted.

The same keyword can have different edge costs for different labels. The unit-weight ablation replaces all costs with one while preserving adjacency, testing whether these association-specific costs help retrieval.

Each observed text contributes a correlation value to its keyword--label pair. Averaging these values summarizes repeated associations without concatenating every support text into the classification prompt.

\subsection{Merging label rounds}
\label{sec:gorag:merge}

At each round, we merge the new graph with the accumulated index by taking the unions of their node and edge sets. Earlier labels and their associations remain available for subsequent retrieval.

GORAG also introduces edges between newly introduced and earlier label nodes. These bridges support connections between parts of the graph indexed in different rounds. Let $\mathcal{M}_y^r$ denote the keyword neighbors of label $y$. For a new label $y_n$ and an earlier label $y_o$, GORAG reports
\begin{equation}
w_{y_n,y_o}^r=\frac{1}{2}\left(
\frac{\sum_{v\in\mathcal{M}_{y_n}^r}w_{v,y_n}^r}{2|\mathcal{M}_{y_n}^r|}
+\frac{\sum_{v\in\mathcal{M}_{y_o}^r}w_{v,y_o}^r}{2|\mathcal{M}_{y_o}^r|}
\right).
\label{eq:gorag:labelbridge}
\end{equation}
Here $w_{y_n,y_o}^r$ is the bridge cost, $\mathcal M_{y_n}^r$ and $\mathcal M_{y_o}^r$ are the keyword-neighbor sets of the new and earlier labels, and $w_{v,y}^r$ is a keyword--label edge cost. The formula uses costs incident to both labels. These factors determine the relative cost of traversing a label bridge rather than a keyword association.
% Verification issue G6: preserve exact reported factors; source wording says weighted average.

Label bridges connect graph regions introduced in different rounds. Unlike keyword edges, which record observed term--class associations, they are created during graph merging.

\section{Adaptive Candidate Label Retrieval}
\label{sec:gorag:retrieval}

For a query $t$, GORAG extracts keywords using the indexing procedure and partitions them according to whether they already occur in the current graph node set $\mathcal{V}^r$. Write these sets as $\mathcal{V}_{\mathrm{exist}}^t$ and $\mathcal{V}_{\mathrm{notexist}}^t$. The existing keywords become the terminals for current retrieval. The unseen keywords are held for online insertion after classification. This partition restricts current retrieval to keywords with indexed label associations.

Retrieval seeks a low-cost connected structure that contains the mapped terminals. Label nodes encountered in this structure form the candidate set $\widehat{\mathcal{Y}}_t^r$. Connecting several terminals can select intermediate labels and keywords. The graph therefore determines the number of candidate labels through the returned structure, rather than requiring the same number of labels for all queries. A short query and a query containing several mutually distant indexed terms can produce different retrieval structures.

This terminal-connecting objective is related to the Steiner tree problem. In that problem, the required terminals are a subset of graph vertices, and the solution may use additional vertices to connect them. An ordinary minimum spanning tree instead spans all vertices of its input graph. These objects play distinct roles in GORAG's procedure. GORAG uses these intermediate structures to construct a heuristic connection among the query terminals.

\subsection{Tree and auxiliary-graph operations}
\label{sec:gorag:algorithm}

GORAG uses a greedy terminal-connecting procedure based on Mehlhorn's algorithm~\cite{gorag-mehlhorn1988faster}. The mapped keywords serve as terminals. An auxiliary graph $H$ represents connections between terminals, with edge weights given by path costs. A minimum spanning tree of $H$ selects a collection of terminal connections. Expanding these connections into their underlying paths produces the graph structure used for candidate selection. The language model then receives the labels encountered in this structure.

Once the expanded structure $S_t^r$ is obtained, the candidate set is
\begin{equation}
\widehat{\mathcal{Y}}_t^r=\mathcal{V}(S_t^r)\cap\mathcal{Y}^r.
\label{eq:gorag:candidates}
\end{equation}
Here $S_t^r$ is the retrieved structure, $\mathcal V(S_t^r)$ its node set, $\mathcal Y^r$ the current label set, and $\widehat{\mathcal Y}_t^r$ the resulting candidates. Representative keywords and label descriptions are added to the classification prompt for the labels selected by this intersection.

\section{Classification and Online Indexing}
\label{sec:gorag:online}

GORAG constructs a classification input by concatenating the query text, extracted query keywords, retrieved candidate labels, and representative keywords associated with those labels. With $\mathcal{K}^t$ denoting query keywords and $\mathcal{K}_{\widehat{\mathcal{Y}}_t^r}$ the representative label information, the input is
\begin{equation}
c_t=\operatorname{Concat}\left(t,\mathcal{K}^t,\widehat{\mathcal{Y}}_t^r,\mathcal{K}_{\widehat{\mathcal{Y}}_t^r}\right).
\label{eq:gorag:context}
\end{equation}
Here $c_t$ concatenates query $t$, its keywords $\mathcal K^t$, candidate labels $\widehat{\mathcal Y}_t^r$, and their representative information $\mathcal K_{\widehat{\mathcal Y}_t^r}$. A language model applies the classification instruction $p_{\mathrm{classify}}$ to this input and produces the predicted label $y_t^*$. The graph narrows and describes the alternatives; the language model performs the final text classification.

After the prediction, each keyword in $\mathcal{V}_{\mathrm{notexist}}^t$ is inserted into the graph and connected to the predicted label $y_t^*$. The update can be written as
\begin{align}
\mathcal{V}^r&\leftarrow\mathcal{V}^r\cup\mathcal{V}_{\mathrm{notexist}}^t,\\
\mathcal{E}^r&\leftarrow\mathcal{E}^r\cup\{(v,y_t^*):v\in\mathcal{V}_{\mathrm{notexist}}^t\}.
\label{eq:gorag:update}
\end{align}
Here $\mathcal V^r$ and $\mathcal E^r$ are the current node and edge sets, $\mathcal V_{\mathrm{notexist}}^t$ contains the query keywords absent from the index, and $y_t^*$ is the predicted label. New associations receive weights through the reported weighting mechanism. Later queries can then map terms that were previously absent from the index. The update changes the retrieval source without fine-tuning the language model's parameters.

The prediction precedes insertion, so a new keyword's association can affect later queries but not the prediction that created it. Incorrect predicted labels can propagate through those associations. The offline ablation suppresses online expansion, measuring its contribution relative to an index that receives no such query-dependent additions.

\subsection{Computational organization}
\label{sec:gorag:computation}

The graph separates work performed at a label update from work performed for each query. Offline indexing processes the supplied texts, creates or updates keyword associations, generates label information when available, and merges the round's graph. The cross-round label bridges introduce interactions between the newly indexed and earlier label regions. In the source's abstract operation count, let $\mathcal V_{\mathrm{new}}^r$ be the nodes in the new round graph, $\mathcal D^r$ its labeled training texts, and $\mathcal Y^r$ and $\mathcal Y^{r-1}$ the current and previous label sets. Construction is expressed as
\begin{equation}
O\!\left(|\mathcal{Y}^r||\mathcal{Y}^{r-1}|+|\mathcal{V}_{\mathrm{new}}^r||\mathcal{D}^r|\right).
\label{eq:gorag:constructioncost}
\end{equation}
The two terms count label merging and keyword--text processing. Language-model token costs additionally depend on prompt and output lengths and are measured in the token study.

Each query maps its keywords to the index, retrieves a connecting structure, and constructs a classification prompt. New terms are inserted after prediction, so the index can grow within a round. The prompt contains only the labels selected for the current query.

\section{Experimental Design}
\label{sec:gorag:experiments}

We evaluate GORAG on CAD, WOS, and IFS-Rel. CAD contains social media posts annotated for contextual abuse~\cite{gorag-vidgen2021introducing}. WOS contains academic texts associated with research-area labels~\cite{gorag-kowsari2017hdltex}. IFS-Rel supplies relation-classification examples derived from news text in an incremental few-shot benchmark~\cite{gorag-xia-etal-2021-incremental}. These datasets exercise different label vocabularies and text lengths within the dynamic classification setting.

The four-round split introduces 13 labels across CAD's rounds, 133 across WOS, and 64 across IFS-Rel. The test collections contain 817, 9,396, and 2,560 examples, respectively. IFS-Rel uses 40 test examples per label. Its balanced test allocation differs from the changing class frequencies in the other collections.

\input{chapter/tables/gorag-dataset-table.tex}

The label counts in Table~\ref{tab:gorag:dataset} describe labels introduced in each round. The classifier operates over their cumulative union. Thus the second WOS round adds 53 labels to the 32 labels already introduced, rather than replacing the earlier set by a new 53-label task. This distinction matters when relating the dataset statistics to the size of the classification instruction and to the graph state retained from earlier rounds.

The main few-shot study uses 1, 5, and 10 labeled examples per class. CAD and WOS RAG experiments use Qwen2.5-7B, while IFS-Rel uses GPT-4o. The source reports an Intel Xeon Gold 5220R CPU at 2.20GHz and a single NVIDIA A100-SXM4-40GB GPU for the experiments. IFS-Rel inference uses the GPT-4o service.

Classification accuracy requires an exact match between the model output and the ground-truth label name or number. An output that cannot be matched to the required class is not counted as correct.

\subsection{Compared methods and controls}
\label{sec:gorag:baselines}

The study compares six baselines. Entailment constructs text--label entailment pairs and fine-tunes a classifier~\cite{gorag-xia-etal-2021-incremental}. NaiveRAG retrieves text chunks from the indexed support information. Retrieved context is compressed by LongLLMLingua before classification~\cite{gorag-jiang-etal-2024-longllmlingua}. GraphRAG, LightRAG, and HippoRAG2 supply graph-based retrieval alternatives~\cite{gorag-edge2024local,gorag-guo2024lightrag,gorag-gutierrez2025memory}. The graph retrieval systems are adapted to return classification evidence.

Entailment uses RoBERTa-large for five training epochs, a batch size of 16, a learning rate of $10^{-6}$, and Adam. LongLLMLingua is evaluated with compression rates of 0.75, 0.8, and 0.85, with 0.8 selected in the reported comparison. GraphRAG and LightRAG use local search. The source uses the nano-graphrag implementation for GraphRAG and NaiveRAG and the other baselines' official implementations.

\section{Ablations and Resource Use}
\label{sec:gorag:ablations}

The WOS ablation study uses a one-shot Qwen2.5-7B setting. The offline variant disables online indexing. The unit variant assigns cost one to every graph edge. The offline-and-unit variant removes both features. The keyword variant uses the extracted keywords in place of the complete query text for classification.

\input{chapter/tables/gorag-ablation-table.tex}

In the ablation table, the full method reports 0.4862, 0.4649, 0.4814, and 0.4210 across rounds. The offline variant reports 0.3063, 0.2302, 0.2455, and 0.2156. The unit variant reports 0.4706, 0.4394, 0.4407, and 0.3899. Disabling online insertion causes a larger accuracy drop than replacing weighted edges with unit costs.

The offline-and-unit variant reports 0.2979, 0.2287, 0.2645, and 0.2249. Its third- and fourth-round values exceed those of the offline variant. The effects of removing these components are therefore not strictly additive across rounds. The keyword variant reports 0.4746, 0.4606, 0.4455, and 0.4030, below the full method in each displayed column. The full query provides information useful to the classifier in these experiments even though keywords determine the retrieval terminals.

The publication gives different full-method values in the main and ablation WOS tables without explaining their provenance. Component comparisons here use the full-method row from the ablation table.

\section{Discussion and Chapter Summary}
\label{sec:gorag:discussion}

We proposed GORAG for dynamic few-shot classification. Weighted keyword--label connections determine the candidate set for each query, and the language model classifies the original text using those labels and their descriptions.

Disabling online insertion lowers accuracy, showing the contribution of expanding the index beyond the support sample. Because these additions carry predicted labels, the method couples current classification with the evidence available to later queries.

Keyword extraction restricts the query terms available as retrieval terminals. Sparse support data and limited label descriptions constrain initial graph coverage.

GORAG constructs and updates task-related knowledge without requiring a predefined external graph or model fine-tuning. This supports classification as labels and vocabulary evolve. For question answering and generation, the output requires facts and explanations beyond a candidate label set. The following chapters investigate two extensions of task-related graph retrieval. Chapter~\ref{ch:agrag} studies connected textual evidence and answer coverage, while Chapter~\ref{ch:mgrag} studies query-aware construction and semantic matching across text and images.
